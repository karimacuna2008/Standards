🌐 Python API Client

Cómo consumir APIs REST externas en Python: autenticación, paginación, reintentos y manejo de errores HTTP

¿Qué es?

El estándar de API Client cubre cómo escribir código Python para consumir APIs externas — es decir, cuando el proyecto actúa como cliente HTTP y llama a servicios de terceros (GitHub API, Stripe, Notion, OpenAI, etc.).

Cubre 8 áreas: autenticación, instanciación del cliente, separación de fetch y transform, paginación, reintentos, manejo de errores HTTP, validación de respuestas y logging de llamadas.

Scope: Este estándar es para consumir APIs. Exponer tus propias APIs (como servidor FastAPI) es un estándar diferente: python/api-server.md (pendiente).

¿Para qué sirve?

  • Seguridad: Las credenciales nunca se hardcodean en el código — siempre desde variables de entorno.
  • Resiliencia: Los reintentos con backoff exponencial hacen que el código sobreviva a errores temporales de red o servidores saturados.
  • Mantenibilidad: Separar fetch de transform significa que si la API cambia su estructura, solo tocas la función de fetch. Si cambias qué campos necesitas, solo tocas la de transform.
  • Debuggability: El logging de llamadas API hace trivial diagnosticar qué llamada falló, cuándo y con qué código de error.
  • Completitud: La paginación automática garantiza que nunca te quedes con solo la primera página de resultados por accidente.

¿Por qué este enfoque?

Credenciales en .env: Las API keys hardcodeadas en el código eventualmente llegan al repositorio por accidente. Con .env + gitignore es estructuralmente imposible commitearlas sin notarlo.

Cliente como dependencia (no global): Las variables globales hacen el código difícil de testear y de razonar. Un cliente pasado como parámetro es explícito — cualquier función que lo usa lo declara en su firma.

Solo reintentar 5xx y timeouts: Los errores 4xx (401, 404, 422) son problemas del lado del cliente — reintentar no cambia nada porque el servidor seguirá rechazando la misma petición. Solo tiene sentido reintentar cuando el problema es temporal en el servidor (5xx) o de red (timeout).

Backoff exponencial: Un reintento inmediato después de un error 503 probablemente también fallará — el servidor está sobrecargado. Esperar 2s, luego 4s, luego 8s le da tiempo al servidor para recuperarse.

Nunca retornar None en errores críticos: Si una función puede retornar None tanto cuando "no hay datos" como cuando "la llamada falló", el caller no puede distinguir los dos casos. Raise + excepción hace la diferencia explícita.

Cómo aplicarlo

1. Autenticación — siempre desde .env

import os from dotenv import load_dotenv # ✅ Correcto — desde .env load_dotenv() API_KEY = os.getenv('API_KEY') # ❌ Jamás hardcodeado API_KEY = "sk-1234abcd..." # nunca
  • Llamar load_dotenv() antes de cualquier os.getenv()
  • Si la variable no existe, os.getenv() retorna None — validar antes de usar (ver Error Handling)
  • Nunca loguear ni imprimir la API key, ni parcialmente

2. Cliente como dependencia — crear una vez en main()

# ✅ Instanciado en main(), pasado como parámetro def fetch_users(client: SomeAPIClient) -> list[dict]: return client.get('/users') def main(): client = SomeAPIClient(api_key=API_KEY) users = fetch_users(client) # ❌ Variable global — evitar client = SomeAPIClient(api_key=API_KEY) # al nivel del módulo def fetch_users() -> list[dict]: return client.get('/users') # usa el global implícitamente

3. Separar Fetch de Transform

# ✅ Correcto — funciones separadas def fetch_users(client: SomeAPIClient) -> list[dict]: """Llama la API y retorna datos crudos.""" response = client.get('/users') return response['data'] def transform_users(raw_users: list[dict]) -> list[dict]: """Extrae solo los campos necesarios.""" return [ {'id': u['id'], 'name': u['full_name'], 'email': u['email_address']} for u in raw_users ] # ❌ Mezclados — evitar def get_users(client: SomeAPIClient) -> list[dict]: response = client.get('/users') return [{'id': u['id'], 'name': u['full_name']} for u in response['data']]

Excepción: si usas los datos tal como llegan de la API sin transformación, una sola función es suficiente.

4. Paginación

def fetch_all_users(client: SomeAPIClient) -> list[dict]: all_users = [] cursor = None while True: response = client.get('/users', params={'cursor': cursor, 'limit': 100}) all_users.extend(response['data']) if not response['has_more']: break cursor = response['next_cursor'] return all_users
  • cursor = None para la primera página (la mayoría de las APIs lo ignoran)
  • Siempre un limit explícito — no confiar en el default de la API
  • Acumular en lista local, retornar al final (no procesar dentro del loop — eso es transform)
  • El nombre de campo (has_more, next_page, etc.) varía por API — adaptar el nombre, no el patrón

5. Reintentos con backoff exponencial

import time import logging def fetch_with_retry(client, endpoint: str, max_retries: int = 3) -> dict: for attempt in range(1, max_retries + 1): try: response = client.get(endpoint, timeout=10) if response.status_code == 200: return response.json() if response.status_code >= 500: logging.warning(f"Retry {attempt}/{max_retries} — status {response.status_code}") time.sleep(2 ** attempt) # backoff: 2s, 4s, 8s continue if response.status_code >= 400: raise ValueError(f"Client error {response.status_code} — no retry") except requests.exceptions.Timeout: logging.warning(f"Retry {attempt}/{max_retries} — timeout") time.sleep(2 ** attempt) raise RuntimeError(f"API failed after {max_retries} retries: {endpoint}")
  • Reintentar solo en 5xx y timeouts
  • Backoff exponencial: 2 ** attempt segundos (2s, 4s, 8s)
  • timeout siempre explícito — nunca esperar indefinidamente
  • Raise cuando se agotan los reintentos — no retornar None silenciosamente

6. Manejo de errores HTTP por código

def handle_response(response) -> dict: if response.status_code == 200: return response.json() if response.status_code == 401: raise PermissionError("Invalid or expired API key") if response.status_code == 403: raise PermissionError(f"Access denied: {response.url}") if response.status_code == 404: return {} # Recurso no encontrado — retornar vacío si es opcional if response.status_code == 429: retry_after = response.headers.get('Retry-After', 60) raise RuntimeError(f"Rate limit hit — retry after {retry_after}s") if response.status_code >= 500: raise RuntimeError(f"Server error {response.status_code}")

404Recurso no encontradoRetornar {} si es opcional; raise si es requerido

7. Validación de respuesta

def fetch_users(client) -> list[dict]: response = client.get('/users') data = response.json() if 'data' not in data: raise ValueError(f"Unexpected response: missing 'data' key. Got: {list(data.keys())}") if not isinstance(data['data'], list): raise ValueError(f"Expected list in 'data', got {type(data['data']).__name__}") return data['data']

Validar las claves y tipos que el código usa directamente, antes de usarlos. El mensaje de error debe incluir qué llegó realmente — facilita el debugging.

8. Logging de llamadas API

import logging, time def fetch_users(client) -> list[dict]: logging.info("GET /users") start = time.time() response = client.get('/users', timeout=10) elapsed = round(time.time() - start, 2) if response.status_code == 200: logging.info(f"GET /users — 200 OK ({elapsed}s)") else: logging.warning(f"GET /users — {response.status_code} ({elapsed}s)") return response.json()
