🤖 Python Automation

Cómo escribir scripts CLI y herramientas de automatización en Python: menús, argparse, output y control de flujo

¿Qué es?

El estándar de Automation define cómo estructurar scripts de Python que interactúan con el usuario o que se ejecutan automáticamente desde pipelines. Cubre la decisión entre menú interactivo y argparse, la estructura obligatoria de main(), el patrón de action dict para dispatch, las convenciones de output en consola, el control de cuándo usar sys.exit() vs return, la validación de inputs y el feedback de progreso en operaciones largas.

¿Para qué sirve?

  • Consistencia de output: Los mismos símbolos (✓, ✗, ⚠️, →) en todos los scripts hacen que el usuario sepa qué tipo de mensaje es sin leerlo completo.
  • Scripts seguros de importar: El patrón main() + if __name__ == '__main__' garantiza que ejecutar código no pase al importar el módulo desde otro script.
  • Extensibilidad predecible: El action dict hace que agregar una opción al menú sea solo añadir una línea — no modificar una cadena de if/elif cada vez.
  • Resiliencia en menús: La distinción sys.exit() vs return garantiza que un error en una acción del menú no mata todo el script — el usuario puede seguir usándolo.
  • Trazabilidad en operaciones largas: El feedback de progreso hace que el usuario no asuma que el script se colgó cuando está procesando.

¿Por qué este enfoque?

Menú vs argparse — decidir desde el inicio: Convertir un script de menú interactivo a argparse después de que está hecho es costoso. La decisión debe tomarse al principio basándose en si el script se ejecutará manualmente o automatizadamente.

Action dict en vez de if/elif: Una cadena larga de if/elif para dispatch de menú es el anti-patrón más común en scripts de automatización. Con un diccionario, la lógica de dispatch desaparece — el dict es el menú. Agregar una opción es agregar una entrada al dict, no insertar código en el medio de una cadena condicional.

sys.exit(1) vs return: sys.exit(1) dentro de una acción de menú es destructivo — mata todo el proceso y el usuario pierde el contexto de la sesión. return dentro de una función de menú simplemente regresa al menú — el usuario puede intentar otra opción. La excepción son los errores en la inicialización: si faltan variables de entorno o no hay conexión a la BD, no tiene sentido continuar.

Símbolos de output estandarizados: En una pantalla llena de texto, los símbolos permiten escanear visualmente sin leer. ✓ = OK, ✗ = error, ⚠️ = advertencia, → = en progreso. Cuando todos los scripts los usan igual, el ojo los reconoce automáticamente.

Con qué

argparse (stdlib) sys (stdlib) os (stdlib) input() (builtin)

Todo de la stdlib de Python. No se requieren librerías externas para la mayoría de los scripts de automatización.

Cómo aplicarlo

1. Menú interactivo vs Argparse

SituaciónUsar
El usuario corre el script manualmente, paso a pasoMenú interactivo
El script corre desde CI, cron, o una pipelineargparse
Se encadena con otros scripts o toma parámetros variablesargparse
Herramienta interna de uso ocasional, múltiples pasosMenú interactivo
Si el script alguna vez se automatizará, usar argparse desde el inicio — es mucho más difícil agregar un menú después que al revés.
# Argparse import argparse parser = argparse.ArgumentParser(description='Process data files') parser.add_argument('--input', required=True, help='Input CSV file') parser.add_argument('--output', required=True, help='Output file') parser.add_argument('--verbose', action='store_true') args = parser.parse_args()

2. main() + if __name__ == '__main__' — obligatorio

# ✅ Todo el código ejecutable dentro de main() def show_menu(): print("\n=== Data Tool ===") print(" 1. Import data") print(" 2. Process records") print(" 0. Exit") def process_data(): pass def main(): validate_env() while True: show_menu() choice = input("\nOption: ").strip() if choice == '0': break if __name__ == '__main__': main() # ❌ Código suelto a nivel de módulo — se ejecuta al importar validate_env() # se ejecuta al importar show_menu() # se ejecuta al importar

Las únicas cosas al nivel del módulo deben ser: imports, constantes, y definiciones de funciones/clases.

3. Action Dict — dispatch de menú

# ❌ if/elif — crece sin control def handle_choice(choice: str) -> None: if choice == '1': import_data() elif choice == '2': process_records() elif choice == '3': export_results() # ✅ Action dict — agregar una opción = agregar una línea def main(): actions = { '1': import_data, '2': process_records, '3': export_results, '4': show_stats, } while True: show_menu() choice = input("\nOption: ").strip() if choice == '0': break if choice in actions: actions[choice]() else: print(" ✗ Invalid option") # Con parámetros fijos — usar lambda actions = { '1': lambda: import_data(source='csv'), '2': lambda: process_records(verbose=True), }

4. Convenciones de output

# Símbolos estándar print(" ✓ Users imported successfully") # operación exitosa print(" ✗ File not found: data.csv") # error, operación fallida print(" ⚠️ No records found — skipping") # advertencia, continúa print(" → Processing 150 records...") # operación en progreso # Indentación print("\n=== Export Results ===") # título: sin indentación, línea en blanco antes print(" → Exporting to results.csv...") # acción principal: 2 espacios print(" ✓ 342 records exported") # resultado: 2 espacios print(" - Skipped: 5 duplicates") # detalle/sub-item: 4 espacios print(" - Errors: 0") # Tablas con alineación print(f" {'Name':<20} {'Status':<10} {'Records':>8}") print(f" {'-'*20} {'-'*10} {'-'*8}") for item in results: print(f" {item['name']:<20} {item['status']:<10} {item['count']:>8}")

5. sys.exit(1) vs return

SituaciónUsar
Variable de entorno faltante al iniciosys.exit(1)
Conexión a BD/API falla al iniciosys.exit(1)
Una acción del menú fallareturn (vuelve al menú)
El usuario elige salirbreak en el loop
Error irrecuperable en mitad de ejecuciónsys.exit(1) con mensaje claro
# ✅ sys.exit(1) en inicialización def main(): validate_env() # sys.exit(1) si faltan variables connect_to_db() # sys.exit(1) si no hay conexión # ✅ return en acciones del menú def import_data() -> None: if not os.path.exists('data.csv'): print(" ✗ data.csv not found") return # vuelve al menú, el usuario puede intentar otra cosa # ❌ sys.exit(1) dentro de una acción — mata todo el script def import_data() -> None: if not os.path.exists('data.csv'): sys.exit(1) # el usuario pierde toda la sesión

6. Validación de input de usuario

def get_menu_choice(valid_options: list[str]) -> str: while True: choice = input("\nOption: ").strip() if choice in valid_options: return choice print(f" ✗ Invalid option. Choose from: {', '.join(valid_options)}") def get_int_input(prompt: str, min_val: int, max_val: int) -> int: while True: raw = input(prompt).strip() try: value = int(raw) if min_val <= value <= max_val: return value print(f" ✗ Enter a number between {min_val} and {max_val}") except ValueError: print(" ✗ Invalid input — enter a number") def confirm(prompt: str) -> bool: while True: answer = input(f"{prompt} (y/n): ").strip().lower() if answer in ('y', 'yes'): return True if answer in ('n', 'no'): return False print(" ✗ Enter 'y' or 'n'")

Siempre while True hasta que el input sea válido. Siempre .strip() para eliminar espacios accidentales. Funciones reutilizables — no validar inline en cada lugar.
